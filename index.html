Full-Stack Project Architecture & Viva Q&A

1. Technology Stack

  • Frontend: Semantic HTML5, Custom CSS3, Vanilla JavaScript (ES6+ Fetch API).
  • Backend: Python Flask REST APIs (Flask, Flask-SQLAlchemy, Flask-CORS).
  • Database: PostgreSQL / SQLite via SQLAlchemy ORM (Relational Schema).
  • Version Control: Git & GitHub (Branching, Commit history, .gitignore).

2. Database Schema (Entity Relationship)

  • flights: Stores id, flight_number, airline, origin, destination, depart_time, arrival_time, base_price.
  • bookings: Stores id, pnr (Unique), flight_id (Foreign Key), travel_date, seat_number, total_amount, status.
  • passengers: Stores id, booking_id (Foreign Key), full_name, age, gender, email, phone.

3. Top Viva Questions & Answers

Q: How does SQLite switch to PostgreSQL?
Ans: We use SQLAlchemy ORM. By changing the DATABASE_URL environment variable from sqlite:///skyvoyage.db to postgresql://user:pass@localhost:5432/dbname, SQLAlchemy translates all queries automatically without changing a single line of Python application code.

Q: How do you prevent double-booking the same seat?
Ans: In app.py, the POST /api/book route queries the database: Booking.query.filter_by(flight_id=flight.id, travel_date=date, seat_number=seat, status='CONFIRMED').first(). If a record exists, it returns HTTP 409 Conflict.
